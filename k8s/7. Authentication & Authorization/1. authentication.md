### 일반적인 TLS 통신 흐름

              [client]                                                    [server]
    1.                             -----------요청----------->   
    2.                             <---public key & CA crt---
    3. 안전한 Server인지 CA crt 확인
    4. public key로 대칭키 암호화
    5.                             --------암호화된 대칭키------->
    6.                                                             private key로 암호화된 대칭키 복호화
    7.                         (서로 공유 중인 대칭키로 데이터 암복호화 통신)


### kubernetes API Authentication - 0
- master node에서는 별다른 조치 없이 cli로 kubectl을 통해 kubernetes API 접근이 가능함.
- kubectl이 생성될 때, kubernetes API 접근에 필요한 **Client key**와 **Client crt**를 갖고 생성되기 때문.


### kubernetes API Authentication - 1 (x509 client cert)
- client가 server의 신원을 확인하는 것처럼, server도 client의 신원을 확인해야 함.
- k8s server는 내부적으로 **Client key**와 **Client crt**, **CA key**, **CA crt**를 갖고 있음.
-  k8s cluster 외부에서 kubernetes API Server에 접근하려면 server가 갖고 있는 **Client key**와 **Client crt**가 필요함.
- (**CA crt**는 자신이 안전한 서버임을 client에게 알려주기 위한 인증서임.)
- (client가 **Client key**와 **Client crt**로 server에 요청을 하면, server는 자신이 갖고 있는 CA key와  **CA crt**, **Client key**로 **Client crt**를 만들어 client가 보낸 **Client crt**가 유효한지 확인함.)
- kubectl도 생성될 때 **Client key**와 **Client crt**를 갖고 생성됨. 그래서 kubectl을 통해 kubernetes API에 접근이 가능한 것임.


### kubernetes API Authentication - 2 (kubectl proxy)
- 만약 kubectl에 accept-hosts 옵션으로 8001번 포트에 Proxy를 열어두면, k8s cluster 외부에서 **Client key**와 **Client crt** 없이 kubectl proxy를 통해 kubernetes API 접근이 가능해짐.


### kubernetes API Authentication - 3 (Service Account)
- kubectl 자체를 k8s cluster 외부에 설치하여 kubectl에 접근함으로써 kubernetes API에 접근하는 방법도 있음.
- 대신 이 경우의 kubectl은 k8s cluster에 대한 정보와 user 정보를 묶은 context가 필요함.


    [context]
    cluster: cluster명, url, **CA crt**
    user: user명, **Client key**, **Client crt**


### kubernetes API Authentication - 4
- Service Account가 사용하는 token을 이용하는 방법도 있음.
- namespace를 생성하면 기본적으로 Service Account도 default로 생성되는데, 이 Service Account는 **CA crt**정보와 token이 담긴 Secret을 사용함. 
- (Pod를 해당 namespace에 생성하면, Pod는 default Service Account에 연결되어 token값으로 kubernetes API에 접근 가능하게 됨.)
- token만 있으면 외부에서도 kubernetes API 접근 가능함.
