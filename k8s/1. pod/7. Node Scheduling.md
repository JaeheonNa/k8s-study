### Node 선택 방식
- NodeName: Node의 이름으로 특정 Node를 선택함. 해당 Node가 가용하지 않은 상태라면 스케쥴링 되지 않음.
- NodeSelector: 특정 Label이 달린 Node 가운데, 자원이 가장 넉넉한 Node를 선택함.
- NodeAffinity
  - 특정 Key를 가진 Node를 최우선 선택하고, 만약 특정 Key를 가진 Node가 없으면 자원이 가장 넉넉한 Node를 선택함. 
  - matchExpressions 기능 활용. 가령 - key: ver1이고, operator가 Exists이면, ver1를 키로 갖는 Label이 붙은 Node에 스케쥴링 됨.
  - required 옵션이 붙는다면, 아래 조건을 반드시 만족해야하지만, preferred 옵션이 붙는다면 적절한 Node를 알아서 선택함. \
    preferred는 가중치 옵션을 줄 수 있음.
> Exists: key 일치 확인. \
> DoesNotExists: key 불일치 확인/ \
> In: key가 일치하며, value가 포함되는지 확인. \
> NotIn: key가 일치하며, value가 포함되지 않는지 확인. \
> Gt: key가 일치하며, value가 더 큰지 확인. \
> Lt: key가 일치하며, value가 더 작은지 확인. \

### Pod 집중/분산 방식
- Pod Affinity
  - 특정 Pod가 있는 Node를 선택하는 방식. Pod Affinity 속성을 넣고, 특정 Pod의 Label를 달면 됨.(집중)
  - topologyKey 옵션을 줌으로써, 특정 key를 가진 Node 범위 내에서만 Pod를 찾을 수도 있음.
- Anti-Affinity
  - 특정 Pod가 없는 Node를 선택하는 방식. Anti Affinity 속성을 넣고, 특정 Pod의 Label를 달면 됨.(분산)
  - topologyKey 옵션을 줌으로써, 특정 key를 가진 Node 범위 내에서만 Pod를 찾을 수도 있음.

### Node 할당 제한
- Taint
  - Node에 설정함으로써, Pod들이 Scheduling되지 않도록 하는 방식.
  - effect라는 속성에는 NoSchedule과 PreferNoSchedule 옵션이 존재하며, \
    PreferNoSchedule을 부여했을 경우, Pod가 schedule될 곳을 찾다 못 찾으면 해당 Node에 할당을 허용함.
  - NoExecute 옵션을 주면, Toleration이 안 붙은 Pod는 Node에서 삭제됨.
- Toleration
  - Taint 설정이 된 Node에 Scheduling하는도록 Pod에 면역을 부여하는 방식.
  - key, operator, value, effect 옵션이 존재하며, 모든 값이 다 Taint값과 일치해야 함.
