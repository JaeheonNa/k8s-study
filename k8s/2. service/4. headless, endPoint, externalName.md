### DNS
- k8s cluster 내부에도 DNS server가 생성됨.
- Pod, Service의 Domain Name과 IP가 아래와 같이 저정됨.

| object    | Domain Name                          | IP   |
|-----------|--------------------------------------|------|
| service   | [service명].[namespace명].svc.[DNS명]  | [IP] |
| pod       | [IP].[namespace명].pod.[DNS명]        | [IP] |
- 같은 namespace 안에서는 service는 [service명] 만으로 식별이 가능하지만, Pod는 Domain Name 전체를 사용해야 함.

### Headless
- k8s Cluster 내에서 Pod끼리 통신하기 위해서는 Service를 headless service로 만들어야 함. 
- clusterIP를 None으로 설정함으로써 headless service로 만들 수 있음.
- 그리고 Pod역시 host와 subdomain을 지정해야 함. 통상 host는 pod명으로, subdomain은 service명으로 지정함.

| object    | Domain Name                                 | IP   |
|-----------|---------------------------------------------|------|
| service   | [service명].[namespace명].svc.[DNS명]         | [IP] |
| pod       | [host].[subdomain].[namespace명].pod.[DNS명]  | [IP] |

### EndPoint
- service와 pod를 연결할 때, label로 연결하지만, 실제 k8s 내부적으로는 endpoint를 생성해 연결함.
- endpoint는 service object마다 한 개 씩 존재하며, 그 안에는 pod의 ip:port가 저장됨.
- 사실상 service와 pod가 직접 연결되는 것이 아니라, endpoint를 통해 연결되는 것.


    Service       -->    EndPoint           -->    Pod
    (service1)           (service1)                (pod1)
                         [pod IP]:[pod port]       [pod IP]:[pod port]


### ExternalName
- k8s Cluster 내부의 pod가 k8s cluster 외부 도메인에 접근할 때 사용하는 service의 속성.
- Service에 ExternalName이라는 속성을 부여하고, 도메인(ex- google.com)을 부여하면 됨.
- Pod는 Service에게 해당 도메인으로의 연결을 요청하고, service는 k8s 내부의 DNS server에게 '해당 도메인의 IP가 무엇인가?' 물어봄. (물론 그 전에 DNS Cache를 먼저 찔러보긴 함.)
- 해당 도메인의 IP 정보를 모르는 k8s 내부의 DNS server는 k8s 외부의 DNS server에게 요청을 위임함.
