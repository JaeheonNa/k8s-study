### StorageClass
- pv-volume에 대한 클래스.
- pvc 생성 시 StorageClass를 연결하면, 해당 클래스에 맞게 PV 객체를 생성하고, volume을 연결해 줌.


    apiVersion: storage.k8s.io/v1
    kind: StorageClass
    metadata:
        name: default
        annotations:
            storageClass.kubernetes.io/is-default-class: "true"
    provisioner: kubernetes.io/storages
    parameters:
        adminSecretName: storageos-api
        adminSecretNamespace: storageos-operator
        fsType: ext4
        pool: default

### Dynamic Provisioning
- PVC 생성 시 자동으로 PV를 생성하고, 실제로 Volume과 연결하는 기능. StorageClassName이 필요 함.
- Dynamic Provisioning 기능을 생성하지 않는 경우, PV를 직접 만든 후 PVC를 연결해야하며, Pod를 PVC에 연결해야 PV와 Volume이 연결 됨.


    apiVersion: v1
    kind: PersistentVolumeClaim
    metadata:
        name: pvc-fast1
    spec:
        accessMode:
        - ReadWriteOnce
        resources:
            requests:
                storage: 1G
        storageClassName: [StorageClass 명]


### PV's status
Pod - PVC - PV - Volume
- Available: PV 생성 시 최초 상태.
- Bound: PVC와 연결된 상태. 이후 Pod와 PVC가 연결되면, PV와 실제 Volume이 연결 됨. Pod와 PVC가 끊기는 경우 PV와 volume 간 연결은 유지됨.
- Released: PVC를 삭제해 PVC와 연결이 끊긴 상태.
- Failed: volume과의 연결에 문제가 생긴 상태.

### ReclaimPolicy
- PV가 Release 상태일 때 어떻게 관리할 것인지에 대한 정책
- Retain: default 정책. volume은 보존되지만, PV 재사용은 불가.
- Delete: StorageClass 사용 시 default. PVC 삭제 시 PV도 함께 자동 삭제. Volume의 종류에 따라 volume도 삭제될 수 있음. StorageClass 사용 시 Retain을 적용하려면 아래 처럼 직시해줘야.
- Recycle: Deprecated. 사용하지 않는 걸 권장. 고려 안 해도 되므로 내용 생략.


    apiVersion: storage.k8s.io/v1
    kind: StorageClass
    metadata:
        name: default
        annotations:
            storageClass.kubernetes.io/is-default-class: "true"
    reclaimPolicy: Retain
    provisioner: kubernetes.io/storages
    parameters:
        adminSecretName: storageos-api
        adminSecretNamespace: storageos-operator
        fsType: ext4
        pool: default
